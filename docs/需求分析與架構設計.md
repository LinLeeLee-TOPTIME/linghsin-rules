# 需求分析與架構設計

## 一、專案目標

打造一款 **iOS 與 Android 皆可使用的行動 App**，提供以下三大核心功能：

1. **SOP 規範流程展示** — 讓使用者可依分類瀏覽、查看作業標準流程 (Standard Operating Procedures)。
2. **預約功能** — 使用者可選擇項目、日期、時段送出預約。
3. **行事曆 / 行程管理** — 以月曆方式檢視自己的預約與行程。

## 二、使用者角色 (User Roles)

| 角色 | 權限 |
| ---- | ---- |
| 一般使用者 (Customer) | 瀏覽 SOP、進行預約、查看自己的行事曆 |
| 管理員 (Admin)（未來擴充） | 新增/編輯 SOP、管理預約時段、查看所有預約 |

> 本次 MVP (最小可行版本) 先聚焦「一般使用者」。

## 三、功能清單 (Feature List)

### 3.1 SOP 模組
- SOP 分類列表（例：客戶接待、設備操作、安全規範…）
- SOP 詳細內容（步驟條列、注意事項、圖片/影片附件預留欄位）
- 關鍵字搜尋

### 3.2 預約模組
- 選擇服務項目
- 選擇日期（串接行事曆）
- 選擇可預約時段（時段由後端/資料源提供）
- 填寫備註與聯絡資訊
- 送出後產生預約紀錄
- 預約成功 / 失敗提示

### 3.3 行事曆模組
- 月曆視圖 (Month View)
- 點選日期顯示當日行程
- 顏色標記：已預約 / 等待確認 / 已完成
- 進入某筆預約查看詳情、可取消

### 3.4 共通功能
- 首頁 (Dashboard)：顯示今日行程、最近 SOP、捷徑入口
- 個人資料頁 (Profile)
- 底部 Tab 導覽：首頁 / SOP / 預約 / 行事曆 / 個人

### MVP 資料存放策略
- **初期**：使用本機 Mock Data + AsyncStorage（裝置端儲存），可離線運作、快速開發。
- **中期**：導入 **Firebase**（Firestore + Auth + Cloud Functions），不必自建伺服器即可完成登入、資料同步、推播。
- **後期**：若需更嚴謹的商業邏輯，可替換為自建 Node.js / FastAPI 後端。

## 六、資料模型 (Data Model)

### SOP
```ts
type SOP = {
  id: string;
  category: string;        // 分類
  title: string;           // 標題
  summary: string;         // 一句話摘要
  steps: SOPStep[];        // 步驟
  tags: string[];
  updatedAt: string;
};

type SOPStep = {
  order: number;
  title: string;
  description: string;
  note?: string;           // 注意事項
};
```

### Booking
```ts
type Booking = {
  id: string;
  serviceId: string;
  serviceName: string;
  date: string;            // YYYY-MM-DD
  timeSlot: string;        // e.g. "14:00-15:00"
  status: 'pending' | 'confirmed' | 'completed' | 'cancelled';
  note?: string;
  createdAt: string;
};
```

### Service (可預約的服務)
```ts
type Service = {
  id: string;
  name: string;
  durationMinutes: number;
  description: string;
};
```

## 七、畫面導覽設計 (Navigation)

- **Bottom Tabs**：首頁 / SOP / 預約 / 行事曆 / 個人
- **Stack Navigation** 於每個 Tab 內部處理多層頁面
  - 例如 SOP Tab 內：`SOPList` → `SOPDetail`
  - 例如 Booking Tab 內：`SelectService` → `SelectDateTime` → `Confirm`

## 八、開發里程碑

| 階段 | 內容 | 交付物 |
| ---- | ---- | ------ |
| M1 專案雛形 | 建立 Expo 專案、導覽架構、首頁與 SOP 模組 | 可執行的 App 骨架 |
| M2 預約 + 行事曆 | 完成預約流程與月曆視圖、資料以本機儲存 | 可做離線完整流程 |
| M3 雲端整合 | 導入 Firebase 登入與 Firestore | 多裝置同步、真正可上線 |
| M4 管理後台 | Web 後台給管理員 | 完整管理閉環 |

## 九、非功能性需求 (Non-functional)

- **相容性**：iOS 14+ / Android 9+
- **語系**：繁體中文為主
- **可維護性**：TypeScript、模組化資料夾結構
- **可擴充性**：資料層與 UI 層分離，未來替換後端不必動 UI
- **隱私**：預約資訊為個資，日後接 Firebase 時需啟用 Auth 與規則保護
