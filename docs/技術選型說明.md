# 技術選型說明（給非技術背景閱讀）

## 什麼是「技術偏好」？

做一個 App 就像蓋房子，會有「用什麼材料、什麼工法」的選擇。這些就是「技術」。
常見選擇有：

| 方案 | 簡單解釋 | 優點 | 缺點 |
| ---- | -------- | ---- | ---- |
| **原生開發 (Native)** | iOS 用 Swift、Android 用 Kotlin **分開寫兩次** | 效能最好、體驗最佳 | 開發成本 2 倍、要養兩組人 |
| **React Native (Expo)** ⭐ | 用一種語言 (JavaScript/TypeScript) 寫一次，iOS & Android **共用一份碼** | 開發快、生態成熟、Facebook/Shopify/Discord 都在用 | 特殊功能偶爾需要原生模組 |
| **Flutter** | Google 出的跨平台方案，用 Dart 語言 | 效能佳、UI 漂亮 | 語言較新、套件較少 |
| **WebView 包裝 (PWA/Ionic)** | 把網頁塞進 App | 最快 | 體驗較差 |

---

## 我為您的專案建議：**React Native + Expo**

### 為什麼？

1. **一份程式碼，iOS 和 Android 都能跑** — 省時間、省錢。
2. **Expo 幫你處理最麻煩的打包與更新** — 不用自己裝 Xcode / Android Studio 也能先在手機上測試。
3. **TypeScript 協助你之後擴充時不容易寫錯** — 等於程式有「安全帶」。
4. **社群與套件超豐富** — 行事曆、表單、推播通知等幾乎都有現成套件。
5. **未來要接後端非常容易** — Firebase、Supabase 這類「免後端」服務可直接使用。

### 本專案使用的技術組合

| 類別 | 使用的工具 | 作用 |
| ---- | ---------- | ---- |
| 語言 | **TypeScript** | 讓程式更安全、好維護 |
| 框架 | **React Native (Expo SDK 51)** | App 主體 |
| 導覽 | **React Navigation** | 控制頁面之間怎麼跳轉 |
| 行事曆 | **react-native-calendars** | 月曆元件 |
| 狀態管理 | **React Context + Hooks** | 管理資料（初期夠用） |
| 本機儲存 | **AsyncStorage** | 把預約存在手機上 |
| 日期工具 | **dayjs** | 處理日期時間 |
| 未來後端（建議） | **Firebase (Firestore + Auth)** | 登入、雲端資料庫、推播 |

## 未來升級路線

```
現在：本機資料 (Mock + AsyncStorage)
  ↓
下一階段：Firebase 雲端同步 + 使用者登入
  ↓
需要進階商業邏輯時：自建 Node.js / FastAPI 後端
```

這樣您可以 **先跑起來驗證想法**，再慢慢長大，不會一開始就花大錢。

## 如何把這個 App 跑起來？

需要先在您的電腦安裝：
1. **Node.js** (LTS 版) — https://nodejs.org
2. **Expo Go** App（到 iOS App Store / Google Play 商店搜尋 "Expo Go" 下載到手機上）

然後在 `app/` 資料夾執行：

```bash
cd app
npm install
npx expo start
```

會出現一個 QR Code，用手機上的 **Expo Go** 掃描，App 就會直接跑在您的手機上了！
iOS 與 Android 都適用。

---

## 想直接上架到 App Store / Google Play？

Expo 提供 `eas build` 指令，可以幫你打包成 `.ipa` (iOS) 與 `.aab` (Android) 上架檔案。
這部分可在功能完成後再處理，不急於一開始。
